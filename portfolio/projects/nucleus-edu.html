Nucleus EDU — School ERP Platform

Architecting and leading the ground-up rewrite of a legacy school management system into a modular, multi-tenant, API-first platform.

ASP.NET Core 6 Angular 14 SQL Server JWT AWS S3 Azure DevOps Multi-tenant

Fountainhead School — a leading IB Board school in Surat — ran on an aging ASP.NET Framework platform that had grown organically for years. It worked, but it was a single-tenant monolith that was increasingly hard to extend, slow on high-volume screens, and impossible to scale to multiple campuses. I led the ground-up rewrite.

The problem

The legacy system had three fundamental limitations. First, it was single-tenant — each campus needed a separate deployment and database, multiplying maintenance. Second, the UI and business logic were tightly coupled, so every change risked breaking something unrelated. Third, several high-traffic screens (attendance, fees, admissions) had grown slow as data accumulated, with page loads pulling thousands of unpaginated rows.

The approach

I designed a modular, API-first architecture: a clean ASP.NET Core 6 REST API as the single source of truth, and an Angular 14 SPA consuming it. The API is secured with JWT and role-based authorization; every module is a bounded slice with its own controllers, services, and DTOs.

The key architectural decision was multi-tenancy via tenant-based connection resolution. Rather than one deployment per campus, a single deployment resolves the correct database connection per request based on the authenticated tenant — driven by environment configuration, not hard-coded values.

Single API deployment · per-request tenant resolution · isolated per-campus databases

What I built

  • A RESTful API layer with JWT authentication and role-based authorization, securing 10+ frontend modules: Admissions, HRIS, Assessments, Student Portfolio, Transport, Fees, Wellbeing, Inventory, and Ticketing.
  • Tenant-based connection resolution so one deployment cleanly serves multiple campuses with isolated data.
  • An ERPNext Lead synchronization integration for Admissions — automating inquiry hand-off between ERP and CRM and eliminating duplicate manual entry.
  • Integrations: Google OAuth login, WhatsApp route notifications for Transport, AWS S3 document storage, and bank-statement CSV import for fee reconciliation.

The hard part: performance at scale

As daily usage scaled past 2,000 users, several modules that queried large tables started to drag. I profiled the slow paths with SQL Profiler, then:

  • Rewrote the heaviest stored procedures to eliminate redundant scans and correlated subqueries.
  • Added and tuned indexes to match real query patterns.
  • Introduced server-side pagination so grids fetch one page at a time instead of thousands of rows.
The result: high-volume screens stayed responsive as the platform grew, with no infrastructure upgrade required — just better data access.

My role

I owned the architecture and led technical delivery for a 4-developer team — running structured code reviews and knowledge-transfer sessions (Git strategy, API design, SQL performance), and managing the backlog in Azure DevOps with an Epic/Feature/Story hierarchy, sprint planning, and OData reporting.

Outcome

Nucleus EDU replaced the legacy monolith with a maintainable, multi-tenant platform that scales across campuses and gives each module room to evolve independently. It serves 2,200+ students, staff, and parents daily and remains the backbone of the school's operations.
